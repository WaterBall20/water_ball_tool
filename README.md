## Overview

An all-in-one command-line toolkit written in **Rust**. Currently provides three core features:

- **File Finder** (`ff`) — Multi-threaded parallel directory-tree scanner that emits a JSON file manifest. Supports
  symlink cycle detection and optional per-file hashing (MD5/SHA-1/SHA-2/BLAKE2b/BLAKE3/CRC32).
- **WaterBall Files Pack** (`wbfp`) — Custom binary archive format supporting pack, unpack, BLAKE3 hash verification,
  and a read-only TUI browser with a reserved preview pane.
- **Music Player** (`mp`) — Terminal music player for audio files and directories: interactive TUI with play/pause,
  next track, volume, playlist view and a debug window with live logs; playlist modes are selectable with `-m/--mode`.

## Usage

### File search `ff`

```bash
# Search the current directory
water_ball_tool ff .

# Search a directory and write JSON output
water_ball_tool ff ./src result.json

# Skip symlinks
water_ball_tool ff /path/to/dir output.json -s

# Compute hashes and include them in the JSON output (positional, after the output path)
water_ball_tool ff ./src result.json sha256 blake3

# All supported hash algorithms at once
water_ball_tool ff ./src result.json all
```

`HASH` is an optional multi-value positional argument (path, output path, then hashes). Accepted values:
`all`, `md5`, `sha256`, `sha512`, `sha1`, `blake3`, `blake2b`, `crc32` (aliases: `*`, `m5`, `s256`, `s512`, `s1`, `b3`,
`b2b`, `crc`). Hashing forces single-threaded file discovery; hashing itself runs on a separate worker pool.

### Pack `wbfp p`

```bash
# Pack a directory into a water ball pack file (separate manifest .wbm by default)
water_ball_tool wbfp p ./src my.pack

# No manifest separation (all data in a single .pack file)
water_ball_tool wbfp p ./src my.pack -n
```

Packing into an existing pack opens and updates it. With write optimization on (default), files whose size and mtime
match the pack are skipped and reported as done; `-w`/`--no-write-optimization` rewrites them.

### Unpack `wbfp u`

```bash
water_ball_tool wbfp u my.pack ./output_dir
# BLAKE3 hash verification per file before extraction; failed files are skipped with a warning:
water_ball_tool wbfp u -H my.pack ./output_dir
```

### Hash verify `wbfp h`

```bash
water_ball_tool wbfp h my.pack
```

### Browse `wbfp b`

```bash
# Open a pack in the read-only TUI browser
water_ball_tool wbfp b my.pack
```

### File management (no subcommand)

```bash
# Open the file manager without a pack
water_ball_tool wbfp

# Open a pack directly in the manager
water_ball_tool wbfp my.pack
```

Without a subcommand, `wbfp` is a TUI-only file manager: local filesystem on the left, an optional pack in the middle
and preview on the right. A pack path is optional; bare `wbfp` starts with the middle pane hidden. Preview folds first
when the terminal is narrow, then the local pane; the pack pane stays visible. Local files are probed by their
WBFilesPack header (not by extension) and valid packs are marked with `◆`; pressing `⏎` on one opens it.

`y`/`x` copy/move the selected entry to the other namespace: when both lists are visible they start the transfer
directly; on a narrow terminal the app switches to the other list, shows the operation and source path in the header,
and waits for `v`. `c`/`m` copy/move inside the same namespace and open a same-kind destination pane (the source list
becomes read-only); `v` confirms and `Esc` cancels. `r` renames in place with a prefilled, fully selected input; `Del`
deletes after a `y/n` confirmation. Every copy/move runs as a background job with the recommended worker count, and the
right pane shows the same task card and per-file progress as the subcommand modes. `--no-tui` and non-TTY stdout/stdin
are rejected for this form.

`p`, `u` and `h` keep their existing single-pane layout: the file list is read-only, per-file status is shown beside
each
row, and the right pane is reserved for a future content preview. While a job runs, the same pane shows a task list —
active files first with their own progress, completed files below. Worker threads enqueue progress events (rate-limited)
so the task list never blocks file I/O. `--no-tui` keeps the classic progress-bar output; a non-TTY stdout/stdin falls
back
to it automatically.

TUI keys: `q`/`Ctrl+C` quit, `↑`/`↓` move, `⏎` enter a directory or open a probed pack, `←` go to the parent,
`PageUp`/`PageDown` page, `Home`/`End` jump, `Tab` switch panes in the manager, `y`/`x` cross-namespace copy/move,
`v` paste or confirm, `c`/`m` same-namespace copy/move, `r` rename, `Del` delete, `Ctrl+W` close the pack, `p` toggle
the preview, `F12` opens the debug popup, `?` help. `Esc` cancels the current operation (picker, pending transfer,
rename, or delete confirmation) before going to the parent. While a job runs, `q` quits after it finishes.
Windows uses the same VT mouse input as `mp`; all platforms support left-click select, double-click open and wheel
scroll. If mouse capture cannot start, the TUI stays keyboard-only.

### Music player `mp`

```bash
# Play files and/or directories (default mode: sequential-loop)
water_ball_tool mp ./music

# Initial volume (0.0–1.0, default 0.75) and shuffle mode
water_ball_tool mp ./music -v 0.5 -m shuffle

# Play modes: sequential-loop (default), sequential, repeat-one, shuffle, periodic-shuffle
water_ball_tool mp ./music --mode repeat-one

# Verbose output (long option only)
water_ball_tool mp ./music --verbose

# Start playing automatically once the first track is found
water_ball_tool mp ./music --autoplay
```

After the TUI starts: `n` (next track), `←`/`→` (seek 5 s per tap; hold to preview and release to jump), space
(play/pause), `p` (pause), `P` (play), `↑`/`↓` (scroll the playlist),
`PageUp`/`PageDown` (page), `Home`/`End` (ends), mouse wheel (scroll three lines), left double-click on a playlist row
(play that track), `+`/`-` (volume), `F12` (debug popup, logs in its right pane), `e` (effects window; `↑`/`↓` select,
`Space` toggle; format-changing effects such as the resampler are fixed), `:` (command mode: `quit`, `play`,
`pause`, `toggle`, `next`, `prev`, `seek <mm:ss|±N>`, `vol`, `mode`, `goto`, `debug`, `effects`, `help`; `seek` jumps
within the current track),
`q`/`Esc`/`Ctrl+C` (quit). Volume has a compact percentage gauge to the right of the progress bar; the footer keeps only
quit, next, play/pause, debug (F12), effects and command buttons. The main page's right side is reserved for later use;
logs appear in the right pane of the Debug window. Volume values outside 0.0–1.0 are
rejected with an argument error before playback starts. The playlist shows only the visible rows and follows the current
track on a track change. Debug builds also write `debug`-level records (including key/mouse events and panics) to
`temp/logs/music_play/` inside the project, so an unexpected TUI exit can be inspected afterwards; release builds keep
the log file in the user data directory. On Windows the TUI uses VT input and SGR mouse reports; if the terminal cannot
enable VT input, the mouse is disabled and keyboard input keeps working.
Directories are scanned in a background thread; tracks appear in the playlist as they are found. Sequential modes load
the first track as soon as it arrives; shuffle and periodic-shuffle wait for 5 tracks (or initialize with fewer when the
scan finishes early). Without `--autoplay` the first track is only loaded and stays paused — press space or `P` to
start.

## WBFP Format

A custom binary archive format with the following key features:

| Feature                     | Description                                                                                                                                                                                                                                                                |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **A/B atomic writes**       | Manifest data blocks use dual-block alternating writes; at least one complete version survives a crash                                                                                                                                                                     |
| **BLAKE3 hashing**          | File data integrity verification                                                                                                                                                                                                                                           |
| **Incremental save**        | Dirty-flag tracking; only changed parts are written                                                                                                                                                                                                                        |
| **Garbage collection**      | Auto-merges adjacent free blocks and reuses freed space                                                                                                                                                                                                                    |
| **Virtual file add/delete** | `create_dir_all`/`create_file` to create; `delete_file`/`delete_dir_all`/`erase_file`/`erase_dir_all` to delete/erase: delete removes metadata only (data blocks are GC'd, not overwritten), erase overwrites to disk first (Zero/Random/DoD 5220 strategies) then removes |
| **TUI file manager**        | No-subcommand TUI: local filesystem left, optional pack middle, preview right; preview folds first, then the local pane; pack files are probed by header and marked `◆`                                                                                                    |
| **Background transfer**     | `y`/`x` and `c`/`m` copy/move local ↔ pack or within one namespace through `JobSpec::Transfer`; uses the recommended worker count and shows the subcommand-style job card                                                   |
| **Header probe**            | `probe_pack(path)` reads only the file header and does not acquire `.lock`; used by the manager to mark pack files before opening                                                                                                                                          |
| **Same-directory rename**   | `rename(from, to)` changes the leaf name in place and rewrites only the containing `PackStruct` block; cross-directory moves require a separate API; rejected while a handle is open                                                                                       |
| **Move + rename**           | `move_entry(from, to)` relocates to an existing parent and may also change the leaf name; updates ancestor directory counts; no data copy or hash recompute                                                                                                                |
| **Progressive save**        | Auto-saves periodically while data or files are written                                                                                                                                                                                                                    |
| **Process write lock**      | `.lock` file + PID for process-level mutual exclusion                                                                                                                                                                                                                      |
| **Manifest separation**     | Optionally split index data into a `.wbm` file                                                                                                                                                                                                                             |

Full specification: [`docs/en_US/wb_files_pack/manifest-data.md`](docs/en_US/wb_files_pack/manifest-data.md)

**Implementation notes**

- `mp` keeps the decoder's symphonia format reader/decoder and its track metadata together in a single `DecoderSession`
  under one lock; track changes replace or take the whole session, so an "engine present but metadata missing" state
  cannot occur.
- Command-layer threads (`ff`/`wbfp`/`mp`) are created with `thread::Builder`; a spawn failure is returned as an error
  (never panics, never silently ignored). `mp --volume` outside 0.0–1.0 is rejected with an argument error.
- Branches reachable only when an internal invariant is broken abort via `unreachable!` (logic errors); genuine runtime
  failures (I/O errors, spawn failures, invalid CLI input) are returned or reported instead.
