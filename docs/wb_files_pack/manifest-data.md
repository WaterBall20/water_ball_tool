# 水球包文件二进制格式规范

_创建：2026/02/27 &emsp; 最后更新：2026/06/17_

---

## 一、总体架构

一个水球包文件（`.pack`）由三层组成：

| 层次         | 说明                                                | 存储位置                            |
|------------|---------------------------------------------------|---------------------------------|
| **文件头**    | 魔数、版本、标志位、内嵌属性                                    | `.pack` 文件开头                    |
| **清单（索引）** | Attribute、PackStruct、PackFileMetadata、DataPosList | 默认分离为 `.wbm` 文件，也可嵌入 `.pack` 尾部 |
| **数据区**    | 虚拟文件的实际二进制内容                                      | `.pack` 文件数据区                   |

数据在清单中以 **清单数据块（ManifestDataBlock）** 为单位存储，通过 A/B 双块机制实现原子更新。

> **约定**：本文所有整数均使用 **小端序（Little-Endian）** 存储，布尔位序采用 **MSB-first**（最高位为位 0，即 `>> 7` 取得）。

## 二、文件头 FileHeader

`.pack` 文件的前 `FILE_HEADER_BLOCK_LEN` 字节为文件头块，结构如下：

### 2.1 基本信息（前 DATA_BLOCK_LEN 字节内）

| 偏移 | 字节数 | 字段        | 说明                                                                              |
|----|-----|-----------|---------------------------------------------------------------------------------|
| 0  | 11  | type_name | 魔数，固定值 `"WBFilesPack"` (0x57 0x42 0x46 0x69 0x6c 0x65 0x73 0x50 0x61 0x63 0x6b) |
| 11 | 2   | version   | 文件格式版本，当前 `[0, 2]`                                                              |
| 13 | 1   | bool_data | 按二进制位表示的标志位                                                                     |
| 14 | 8   | pack_len  | 包文件总长度（字节）                                                                      |
| 22 | —   | _padding_ | 填充至 `DATA_BLOCK_LEN`(128) 字节                                                    |

### 2.2 标志位 (bool_data)

| 位序(MSB) | 掩码            | 字段              | 说明                |
|---------|---------------|-----------------|-------------------|
| 0       | `0b1000_0000` | cow             | 是否启用写时复制          |
| 1       | `0b0100_0000` | s_manifest_file | 是否分离清单到 `.wbm` 文件 |

### 2.3 内嵌属性

在偏移 `DATA_BLOCK_LEN`(128) 处直接内嵌了一份 **属性（Attribute）**
的清单数据块，用于快速读取包文件的核心索引信息。格式与 [第五节 属性](#五属性-attribute) 完全一致。

`FILE_HEADER_BLOCK_LEN = DATA_BLOCK_LEN + MANIFEST_ATTRIBUTE_BLOCK_LEN`

> **MANIFEST_ATTRIBUTE_BLOCK_LEN**
> 由属性数据的实际大小按清单数据块规则计算得出，见 [第六节](#六清单数据块-manifestdatablock)。

## 三、清单索引总体结构

清单索引（`.wbm` 或 `.pack` 尾部）包含以下逻辑区块，通过属性中的文件指针串联：

```
┌─────────────────────────┐
│  数据区空闲 DataPosList  │ ← empty_data_pos_list_pos 指向
├─────────────────────────┤
│  清单空闲 DataPosList    │ ← manifest_empty_data_pos_list_pos 指向（仅分离模式）
├─────────────────────────┤
│  根结构 PackStruct       │ ← root_struct_pos 指向
│    ├─ PackStructItem    │
│    │   └─ 子 PackStruct  │ ← struct_file_pos 指向
│    ├─ PackStructItem    │
│    │   └─ PackFileMetadata │ ← metadata_file_pos 指向
│    └─ ...               │
└─────────────────────────┘
```

## 四、通用数据结构

### 4.1 数据位置列表 DataPosList

`DataPosList` 是一组 `(位置, 长度)` 对的通用格式，用于追踪数据区间的分配情况。它在两处场景中使用：

| 场景          | 存放位置                                                                                             | 含义              |
|-------------|--------------------------------------------------------------------------------------------------|-----------------|
| **空闲空间追踪**  | `PackIO.empty_data_list`、`WBFilesPackManifest.attribute.empty_data_pos_list_pos` 指向的 DataPosList | 记录当前可复用的空闲区域    |
| **已分配空间追踪** | `PackFileMetadata.file_type.data_pos_list`                                                       | 记录该虚拟文件占据的数据块位置 |

#### 序列化格式

| 偏移 | 字节数        | 字段    | 说明               |
|----|------------|-------|------------------|
| 0  | 8          | count | 数据位置项的数量         |
| 8  | 16 × count | items | 数据位置项列表，每项 16 字节 |

#### 数据位置项

| 偏移 | 字节数 | 字段  | 说明       |
|----|-----|-----|----------|
| 0  | 8   | pos | 起始文件指针位置 |
| 8  | 8   | len | 长度（字节）   |

> **对齐约定**：数据区的分配和回收均以 `DATA_BLOCK_LEN`(128字节) 对齐，数据块则以 `DATA_DATA_BLOCK_LEN`(4MiB) 对齐。

## 五、属性 Attribute

包文件的全局元信息，**常驻内存**，序列化后存储在清单数据块中。

### 5.1 序列化格式（共 61 字节）

| 偏移 | 字节数 | 字段                               | 说明                                  |
|----|-----|----------------------------------|-------------------------------------|
| 0  | 2   | version                          | 当前索引格式版本，值 = `MANIFEST_VERSION`(10) |
| 2  | 2   | version_compatible               | 兼容的最低解析器版本                          |
| 4  | 1   | bool_data                        | 按二进制位表示的标志位                         |
| 5  | 8   | empty_data_pos_list_pos          | 指向数据区空闲空间的 DataPosList 文件指针         |
| 13 | 8   | manifest_empty_data_pos_list_pos | 指向清单文件空闲空间的 DataPosList 文件指针（仅分离模式） |
| 21 | 8   | manifest_file_len                | 清单分离文件的长度（分离模式有效）                   |
| 29 | 8   | root_struct_pos                  | 根结构（`PackStruct`）的文件指针位置            |
| 37 | 8   | file_count                       | 文件总数（不含目录）                          |
| 45 | 8   | dir_count                        | 目录总数                                |
| 53 | 8   | data_len                         | 所有文件数据的实际总大小                        |

### 5.2 标志位 (bool_data)

| 位序(MSB) | 掩码            | 字段  | 说明       |
|---------|---------------|-----|----------|
| 0       | `0b1000_0000` | cow | 是否启用写时复制 |

### 5.3 版本兼容性

打开文件时校验规则：

- `version == MANIFEST_VERSION`：完全兼容
- `version < MANIFEST_VERSION_COMPATIBLE`：版本过低，拒绝解析
- `version_compatible > MANIFEST_VERSION`：版本过高，拒绝解析
- 其他情况：尝试兼容读取

## 六、清单数据块 ManifestDataBlock

所有索引数据（Attribute、PackStruct、PackFileMetadata、DataPosList）均存储在此类数据块中。数据块以 `DATA_BLOCK_LEN`(128字节)
为最小对齐单位。

### 6.1 A/B 双块机制

为保证写入原子性，每个清单数据块内部等分为 **A 块** 和 **B 块**，交替写入：

```
┌───────────────────── A 块 ─────────────────────┬───────────────────── B 块 ─────────────────────┐
│ data_len(8) │ ver(4) │ hash(8) │ 实际数据(...) │ ver(4) │ data_len(8) │ ver(4) │ hash(8) │ ... │ ver(4) │
└────────────────────────────────────────────────┴────────────────────────────────────────────────┘
```

- 写入时选择版本号 **较小** 的那个块覆盖（version+1），另一个块不受影响
- 即使写入中途崩溃，仍有一个完整块可读取
- 读取时取版本号 **较大** 且校验通过的块
- **每个 A/B 块的头部和尾部各存一份版本号**，用于快速完整性校验（头部=尾部则块完整）

### 6.2 A/B 块头部格式（各 20 字节 + 数据）

| 偏移 | 字节数      | 字段       | 说明                       |
|----|----------|----------|--------------------------|
| 0  | 8        | data_len | 实际用户数据的长度                |
| 8  | 4        | ver      | 版本号，单调递增                 |
| 12 | 8        | hash     | 实际数据的 BLAKE3 哈希（取前 8 字节） |
| 20 | data_len | data     | 实际用户数据                   |

A/B 块的尾部（最后一个字节前 4 字节）存储与头部相同的 ver 值。

### 6.3 块大小计算

```
A/B half 最小占用 = 8 + 4 + 8 + data_len + 4  = 24 + data_len 字节
块总大小 = ceil((24 + data_len) × 2 / DATA_BLOCK_LEN) × DATA_BLOCK_LEN
```

## 七、结构 PackStruct

结构表示目录树中的一个节点，包含该目录的所有子结构项。

### 7.1 序列化格式

结构由连续的 **结构项（PackStructItem）** 数据拼接而成：

```
┌──────────────┬──────────────┬─────┐
│ 结构项数据1   │ 结构项数据2   │ ... │
└──────────────┴──────────────┴─────┘
```

- 每个结构项自带长度前缀，通过读取长度边界来遍历
- 结构数据整体存入一个清单数据块

---

## 八、结构项 PackStructItem

结构项是目录树的基本单元，表示一个文件或子目录。

### 8.1 公共字段

| 偏移          | 字节数      | 字段                | 说明                   |
|-------------|----------|-------------------|----------------------|
| 0           | 8        | data_len          | 整个结构项的总长度（含自身）       |
| 8           | 1        | type              | 结构项类型：`0`=文件, `1`=目录 |
| 9           | 2        | name_len          | 名称的字节长度              |
| 11          | name_len | name              | 文件/目录名称（UTF-8）       |
| 11+name_len | 8        | metadata_file_pos | 虚拟文件元数据的文件指针位置       |
| 19+name_len | —        | type_data         | 类型特有数据（见 8.2/8.3）    |

### 8.2 类型 0 — 文件 (File)

类型特有数据为空，总长度 = `19 + name_len`。

### 8.3 类型 1 — 目录 (Dir)

| 相对偏移 | 字节数 | 字段              | 说明                         |
|------|-----|-----------------|----------------------------|
| 0    | 8   | struct_file_pos | 该目录的子结构（PackStruct）的文件指针位置 |

总长度 = `27 + name_len`。

## 九、虚拟文件元数据 PackFileMetadata

每个虚拟文件或目录都有一份元数据，存储在独立的清单数据块中。

### 9.1 公共字段

| 偏移 | 字节数 | 字段        | 说明                       |
|----|-----|-----------|--------------------------|
| 0  | 1   | type      | 元数据类型：`0`=文件, `1`=目录     |
| 1  | 1   | bool_data | 按二进制位表示的标志位              |
| 2  | 8   | len       | 对于文件是数据大小，对于目录是子项数据总大小   |
| 10 | 16  | modified  | 修改时间（自 UNIX 纪元的毫秒数，u128） |
| 26 | —   | type_data | 类型特有数据（见 9.2/9.3）        |

### 9.2 标志位 (bool_data)

| 位序(MSB) | 掩码            | 字段  | 说明       |
|---------|---------------|-----|----------|
| 0       | `0b1000_0000` | cow | 是否启用写时复制 |

### 9.3 类型 0 — 文件 (PackMetadataFile)

| 相对偏移       | 字节数      | 字段            | 说明                                                            |
|------------|----------|---------------|---------------------------------------------------------------|
| 0          | 1        | hash_type     | 哈希算法类型：`1`=BLAKE3                                             |
| 1          | 1        | hash_len      | 哈希值长度（目前 BLAKE3 为 32 字节）                                      |
| 2          | hash_len | hash_value    | 文件数据的哈希值                                                      |
| 2+hash_len | —        | data_pos_list | 记录该文件已分配数据块的 DataPosList（格式见 [4.1 节](#41-数据位置列表-dataposlist)） |

### 9.4 类型 1 — 目录 (PackMetadataDir)

| 相对偏移 | 字节数 | 字段         | 说明                    |
|------|-----|------------|-----------------------|
| 0    | 8   | file_count | 该目录及其所有子目录中的文件总数（累计值） |
| 8    | 8   | dir_count  | 该目录下的所有子目录总数（累计值）     |

### 9.5 哈希校验

读取文件类型元数据时，会自动校验已存储的哈希值：

- 取清单数据块的 `hash` 字段（前 8 字节 BLAKE3）
- 对实际数据重新计算 BLAKE3 并比较前 8 字节
- 不匹配则拒绝加载，防止数据损坏

## 附录：Rust API 参考

本规范对应以下 Rust 公共 API（`src/wb_files_pack/`）：

### 包文件打开（std::fs::OpenOptions 风格）

| 方法 | 说明 |
|------|------|
| `ManagerSync::open(path)` | 以只读模式打开已存在的包文件 |
| `ManagerSync::create_new(path)` | 创建新包文件（默认分离清单、无 COW）。文件已存在则失败 |
| `ManagerSync::options() -> PackOpenOptions` | 返回 `PackOpenOptions` 构造器 |

`PackOpenOptions` 方法链：

| 方法 | 默认值 | 说明 |
|------|--------|------|
| `read(true)` | `false` | 读取模式 |
| `write(true)` | `false` | 写入模式 |
| `create(true)` | `false` | 创建包文件（不存在时创建） |
| `create_new(true)` | `false` | 创建新包文件（存在则失败） |
| `cow(true)` | `false` | 启用写时复制 |
| `separate_manifest(true)` | `true` | 分离清单到 `.wbm` 文件 |
| `open(path) -> Result<ManagerSync>` | — | 根据以上配置打开/创建包文件 |

### 虚拟文件打开（std::fs::File 风格）

`ManagerSync` 上提供便捷方法：

| 方法 | 说明 |
|------|------|
| `ManagerSync::open_virtual_file(path, end_pos)` | 以只读模式打开已有虚拟文件，类似 `File::open` |
| `ManagerSync::create_virtual_file(path)` | 以只写模式创建新虚拟文件，类似 `File::create` |
| `ManagerSync::virtual_file_options() -> VirtualFileOpenOptions` | 返回 `VirtualFileOpenOptions` 构造器 |

`VirtualFileOpenOptions` 方法链：

| 方法 | 默认值 | 说明 |
|------|--------|------|
| `read(true)` | `false` | 只读模式 |
| `write(true)` | `false` | 只写模式 |
| `create_new(true)` | `false` | 创建新文件（存在则失败） |
| `end_pos(bool)` | `false` | 文件末尾位置标记（用于增量写入恢复） |
| `open(sync, path) -> Result<PackVirtualFile>` | — | 在指定 `ManagerSync` 中打开/创建虚拟文件 |

### 虚拟文件读写（PackVirtualFile）

`PackVirtualFile`（原 `PackFileWR`）实现 `Read`、`Write`、`Seek` trait，并根据打开时的访问模式进行权限检查：

- **Read 模式**：`Write` 操作返回 `PermissionDenied`
- **Write 模式**：`Read` 操作返回 `PermissionDenied`
- **ReadWrite 模式**：读写均允许

继承方法：

| 方法 | 说明 |
|------|------|
| `set_len(len)` | 设置虚拟文件长度 |
| `set_modified(ts)` | 设置修改时间戳 |
| `sync()` | 强制刷出待写入数据 |
